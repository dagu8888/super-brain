## 现状（审计证据）

1. 值班室信使 `tools/duty-room/dsh1-courier.py` 以**明文 HTTP** 连接云网关 `http://8.218.106.225:18765`，SSE 长连 + 任务轮询。
2. 认证为**长期 Bearer Token**（viewer token，本地落 `~/.dsh1-courier.json`），无过期、无轮换机制。
3. 节点侧暴露面（同机）：0.0.0.0:5432（PostgreSQL 对公网口监听）、0.0.0.0:8810（MAUS）、C$/D$/E$ 管理共享开启——网关一旦被中间人利用，横向可达性很高。
4. 节点管家即将成为常驻组件，未来对接点：`POST /api/guardian/report`（metrics + agent 状态 + 事件分级），当前在节点侧仅入本地 outbox 队列（`bridge.enabled=false`），**等网关具备 TLS 后一次性打开**。

## 请求内容（按优先级）

| # | 项 | 建议做法 | 影响面 |
|---|---|---|---|
| 1 | **网关 HTTPS** | 云侧 18765 前加 TLS 终结（Caddy/Nginx，Let's Encrypt），或套一层 Cloudflare；HTTP 端口保留过渡期双跑 | 云侧单机配置；节点侧改一行 `GATEWAY` |
| 2 | **令牌短期化** | viewer token 改 JWT（1-24h 过期）+ 刷新端点；或至少提供轮换接口 | courier 与所有 viewer |
| 3 | **心跳/报告端点** | 开放 `/api/guardian/report`（Bearer 鉴权，JSON body，幂等） | 新增，云侧约 30 行 |
| 4 | **限速与来源校验** | 网关侧按 token 限速；可选 mTLS（节点证书） | 低 |

## 节点侧已就绪的部分

- courier 本身不感知 TLS 差异（urllib/requests 透明）；切 HTTPS 只改 `GATEWAY` 常量。
- 管家 bridge 的认证已设计为**只读环境变量 `SB_VIEWER_TOKEN`**，绝不读凭据文件；TLS 就绪后把 `config/guardian.json` 的 `bridge.enabled` 改 true 即开。
- 过渡期若网关双跑（HTTP+HTTPS），节点侧可灰度：先 courier 切 HTTPS，观察 24h，再开管家上报。

## 风险陈述

- 明文 HTTP + 长期 Token：网关凭据在公网链路可被截获；节点凭据一旦泄露，攻击者可向中台投递任务（值班室体系里任务即指令）。
- 本请求不涉及数据出境/合规问题，纯传输层加固。

## 验收标准（中台完成后节点侧自验）

1. `curl https://<网关>/health` 返回 200 且证书链有效；
2. courier 用 HTTPS 跑 24h，SSE 断连重连日志无异常；
3. 管家 outbox 队列开始清空（sent=1）；
4. 旧 HTTP 端口按中台排期关闭。
