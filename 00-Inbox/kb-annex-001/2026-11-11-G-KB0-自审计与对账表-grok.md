## 一、kb_search 定性结论（权威答案）

**结论：kb_search 不是语义检索，也不是 BM25 / SQLite FTS / 关键词打分检索，而是「对整个工作目录逐文件做大小写不敏感的字面子串查找（grep 式）」，无索引、无分词、无排序，凑满条数就停。**

| 事实 | 证据 |
|---|---|
| 入口：`POST /cmd`，`{"cmd":"kb_search","args":{"q":"…"}}` | `90-System/runtime/api_server.py:510-540`；`runtime.py:597` |
| 检索词只认 `q` / `text` / `keyword` 三个参数名，都空就报「空关键词」 | `runtime.py:598-600` |
| `limit` 默认 10，上限 20 | `runtime.py:601-604` |
| `os.walk(ROOT)` 遍历**整个工作目录**，只跳过 `.git` `__pycache__` `node_modules` `incoming` | `runtime.py:606-609` |
| 参与的扩展名：.md .txt .yaml .yml .py .js .json；单文件 >2MB 跳过 | `runtime.py:607, 619-620` |
| 敏感文件过滤（api_tokens*、llm.json、state.db*、.env*、*.db/*.pem/*.key） | `runtime.py:97-104, 613` |
| 匹配算法：`text.lower().find(q.lower())`，整串字面子串；每个文件只取第一个命中位置，前 60 + 后 120 字符做摘录 | `runtime.py:624-630` |
| 无排序：按文件系统遍历顺序先到先得，满 `limit` 即停 | `runtime.py:611-612, 631-633` |
| 另有一条**不同的**检索路径 `_kb_snippets`（中文二字组 + 英文整词，标题×4/标签×3/分类×2/正文 log1p，按覆盖率加权），只扫 10-Knowledge，只给服务器内 chat / research worker 用，chief 调不到 | `runtime.py:1374-1463, 1475, 1525` |

实测（2026-11-11 17:37，grok-chief 口令）：

| 请求 | HTTP | 耗时 | 结果 |
|---|---|---|---|
| `args.q = "Super-Brain"`（命中多） | 200 | 0.42 s | 10 条 |
| `args.query = "Super-Brain"`（参数名不对） | **400** | 0.44 s | `空关键词（q/text/keyword 任选其一）` |
| `args.q = 一个库里没有的词` | 200 | **41.5 s** | 0 条 |

### 为什么 Muse 15:12 的探针报 400 / 超时

1. **400**：用了 `q/text/keyword` 以外的参数名（如 `query`），或 `args` 不是对象；网关把所有 `ok:false` 都映射成 HTTP 400（`api_server.py:540`），所以「参数名错」看起来像「格式被拒」。日志 `50-Events/runtime-2026-11-11.jsonl` 15:12:05 记录 muse-chief `kb_search ok:false`。
2. **超时**：命中少或不命中时要把整个目录走一遍。工作目录里有 Git 不跟踪（.gitignore）的 `90-System/queue/` **约 11.99 万个文件**（trae 10.8 万、dsh 1.18 万）和 `50-Events/*.jsonl` 约 120 MB，全部被扫，单次约 40 秒。客户端超时短于 40 秒就会「超时」。同一日志显示 15:13:03、15:13:20 两次 muse-chief `kb_search ok:true`：**服务器其实算完了，是客户端先放弃了**。
3. 正确用法：`curl -m 90 -X POST http://8.218.106.225:18765/cmd -H "Authorization: Bearer <口令>" -H "Content-Type: application/json" -d '{"cmd":"kb_search","args":{"q":"单个短关键词","limit":10}}'`；用短关键词，不要整句。

### 由此带出的三个问题（不在本级修，列给 P2）

- 检索范围≠真源：扫的是工作目录，不是 Git 跟踪文件，Git 外的队列与日志会参与检索，也会占满前 10 条。
- 整句问题几乎必然 0 命中（字面子串），Agent 只能自己拆关键词。
- 每次未命中约 40 秒满核 CPU（2 核机器），高频调用会拖慢中台。
