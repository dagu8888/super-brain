# U3 金标评测集 v1

## 为什么题目不写在这篇 .md 里

kb_search 会扫仓库里所有 .md / .json / .py 等文件。如果把题目和答案写进 .md，下次回放时 kb_search 会直接搜到这份答案，分数就被污染了。所以**题目、标准答案、出处都放在同目录的 `.tsv` 文件里**（kb_search 不扫 .tsv），这篇只写说明。以后回放也要排除整个 `00-Inbox/kb-annex-001/` 目录。

## 构成（55 题，≥40 ✔）

| 类型 | 题数 | 判分要求 |
|---|---|---|
| 现行状态 CS01–CS18 | 18 | 答出现行值并引用正确页面 |
| 历史事件 HI01–HI08 | 8 | 答出当时发生了什么并引用正确页面 |
| 事实变更 TF01–TF10 | 10 | 问的是旧值，必须答「已失效」并给出新值和新出处 |
| 跨域综合 CD01–CD07 | 7 | 需要合起两处以上来源 |
| 库外拒答 OK01–OK09 | 9 | 库里没有，必须答「没有」 |
| 跨会话偏好 PF01–PF03 | 3 | 15:36 任务包要求的偏好题：答出大古的长期偏好并引用出处 |

TSV 字段：`id, type, question, gold_answer, answer_keys（判对用的关键串）, gold_sources（应引页面）, query_kw（按 SOP 拆出的短关键词）, stale_keys（旧值串）, current_sources（新值出处）`。

## 校验

- 每个 `gold_sources` 都是 Git 跟踪文件；每题至少一个 `answer_keys` 出现在应引页面里（服务器上脚本校验，2026-11-11 17:42 北京时间）。
- 库外题在 Git 跟踪文件里用 `git grep -i` 校验：7 题完全不存在；OK05、OK07 的关键词只作为英文子串出现在 three.min.js、CSS 和一篇对话回执里（与题意无关），保留这两题，用来测「字面匹配带来的假命中」。
- 事实变更题的「新值」有 4 题只在代码或提交里（api_server.py、projects.py、runtime.py），说明这些变更没有回写成知识页，本身就是时效层缺口的证据。
