# Agent 评测体系 · 七维细则与评测集工程

> 来源与对账：懂王Ai 抖音《评测集对 Agent 面试非常重要》（学习收件箱条目 19，用户提供全文转写；其「说好评测 30K 直接拿下、项目可以不问」是招生话术，未核实，不作规划依据）+ 本库 `fde_elite_engineer` §4 七维的精修。**对账结论**：旧七维把「过程」写成一维，本视频把过程拆成三个可独立测的检查（召回完整性、证据忠实度、工具执行真实性）——更可落地，采纳为现行口径；旧第 7 维「业务效果」保留为外环（老板最终为业务结果付钱，不能丢）。`fde_coach` 阶段 3 与各行业包的评测点按本技能执行。

## 1. 总原则

- 评测同时管**结果**和**过程**：最终答案看着对，不等于系统对——过程出问题（少召回一条、编造一个状态），迟早在别的题上爆。
- 数据分**静态与动态**两轨：静态金标集管回归，动态线上采样管漂移与新坏案例；只有静态集的评测，上线三个月就过期。
- 安全与权限是**一票否决维**，不是七分之一：其余维度再高，越权测试不过，整体不过。
- 一句话自检：只会报「金标答对率」一个数的评测，等于没有评测。

## 2. 七维核心（每维：查什么 / 怎么测 / 典型翻车）

**① 结果正确性**——最终回答/产出对不对。测法：金标集（问题+标准答案+评分细则）离线跑批；客观题精确匹配，主观题用 LLM 裁判按细则打分并抽样人工复核。翻车：只测结果时，下面②③的病全被「答案碰巧对」盖住。

**② 检索召回完整性（过程一）**——该召回的有没有**全**召回。核心指标是召回率：每道题预先标注「应命中的证据条目集合」，实测命中几条。原例：问「这个书包有什么特点」，库里明明有 5 条描述，只召回 4 条——最终回答看似正确，仍判**不合格**，因为信息残缺是过程失败。精确率同看（多召无关条目是污染），但本维先保召回下限。

**③ 证据忠实度（过程二）**——回答是否**忠于**召回的证据。测法：把回答拆成事实断言，逐条回指证据出处；无出处断言、与证据矛盾的断言计数。翻车形态：5 条证据全召回了，模型却答出与证据相矛盾的内容（编造参数、张冠李戴）——检索没错，生成在胡说。

**④ 工具执行真实性（过程三）**——Agent 声称做的事，**在真实系统里到底成没成**。原例：用户让点一杯 20 元以下的咖啡，Agent 回「已下单成功」——评测不能到此为止，必须回查后端订单状态：接口可能失败、可能根本没调、模型可能在骗人。测法：凡有副作用的任务，验收一律查**世界状态**（订单/数据库/任务状态）而非模型自述；「声称成功但状态未变」单独记一类最严重的失败。与 `agent_harness_design` 的结果三分法同条：结果未知先查状态，绝不盲重试。

**⑤ 稳定性与异常**——稳定性：同一问题连跑 N 次（原例 5 次），看结果一致率与关键字段漂移。异常要**分类测**，不同类处置不同：接口宕机、执行超时、**任务已完成但回传超时**（这两种超时最容易被混为一谈：前者该重试/补偿，后者只该查状态，盲目重试会重复下单）、部分完成、返回格式损坏。用故障注入集逐类演练并记录恢复路径是否按规程走。

**⑥ 性能与成本**——同题同质下：延迟（P50/P95）、Token 消耗、单任务成本、成功任务成本。用途是给优化验收：改了提示词/换了模型，必须拿出「答对率不降 + 延迟或 Token 降了多少」的对比数，否则「优化」只是感觉。

**⑦ 安全与权限（否决维）**——红队集：越权查询（原例：问「老板的银行卡有多少余额」，正确行为是拒答或走授权流程，而不是真去查）、敏感信息外泄、检索文档里的提示注入、跨用户数据串扰。通过率必须 100%，挂一条即整体不过、上线冻结。

**外环 · 业务效果**——上线后业务指标动没动：咨询解决率、线索跟进时效、节省工时、转化与实收。前七维是工程体检，这一维是老板的账本；用动态数据测，不用金标集测。

## 3. 评测集工程（静态轨）

- **来源**：真实日志与真实失败优先，人工编题补长尾；按维度配比组卷（每维有专属子集，权限集独立成卷）。
- **每条金标四件套**：输入、标准答案/期望状态、评分细则、**维度标签**（这条主要测哪一维）。测工具执行的条目，标准答案要写期望的**世界状态**，不是期望的回复文本。
- **版本治理**：金标集版本化，改细则要留痕；**不许拿金标集调提示词调到过拟合**——留一份从不参与调优的封存集做最终验收（调优集/验收集分离，同回测的样本外纪律）。
- **规模观**：一两百条只是起点不是体系；覆盖度（维度×场景×异常类）比条数重要。

## 4. 动态轨（线上评测）

线上流量按比例抽样自动评（裁判+规则），盯三件事：分数漂移告警、新出现的失败模式聚类、用户负反馈回溯。动态轨产出的坏案例经人工确认后**回流入静态金标集**——这是评测集越用越强的唯一来源，也是与数据中台的咬合点（坏案例先回数据中台清洗，再成金标）。

## 5. LLM 裁判纪律

裁判模型尽量与被测模型不同源；评分必须锚定细则并给出引用/理由；定期用人工标注集校准裁判（报告裁判与人工的一致率）；已知偏差——偏爱长答案、偏爱自家模型风格——靠细则锚定与人工抽检压制。裁判本身的一致率不达标时，评测结果不得用于门禁。

## 6. 门禁与报告

- **回归门禁**：改提示词、换模型、动数据，必跑全量金标；任一维度分数下降即冻结上线，先定位再放行（权限维降到 <100% 直接否决）。
- **评测报告固定格式**：七维+外环逐项分数（带样本量与集版本）、与上一版的增减、最差 5 个坏案例原文、裁判一致率、结论（放行/冻结+理由）。没有坏案例原文的报告不算报告。
