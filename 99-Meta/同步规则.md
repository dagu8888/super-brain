# 强制同步规则

> 唯一信息源 = GitHub `origin/main`。本地 `D:\DSH\Yuan Ai\super-brain` 只是工作副本。

## R1 读写流向
| 操作 | 流程 |
|---|---|
| 读 | `sync.ps1 -PullOnly` → 读本地工作副本（= 云端最新快照） |
| 写 | `writeback.ps1` / `new-note.ps1` → 自动 commit → `pull --rebase` → push |
| 删除/改名 | 仅 lead，手工 git 操作 + 立即 `sync.ps1` |

## R2 冲突处理（云端优先）
1. `sync.ps1` 使用 `git pull --rebase origin main`。
2. rebase 冲突时自动执行 `git checkout --ours -- .`（rebase 中 *ours = 云端基线*），取**云端版本**。
3. 冲突文件清单自动追加到 [[99-Meta/冲突日志|冲突日志]]。
4. 自动解决失败 → `git rebase --abort` 回滚并报错，人工介入。
5. 本地被云端覆盖的内容不自动恢复——需要的话重新读取后二次回写为新提交。

## R3 红线
- 禁止 `git push -f` / `git reset --hard origin/main` 丢弃本地未推提交前不备份。
- 禁止绕过脚本手工改文件后长期不同步（>24h 视为违规）。
- 禁止本地独立存储核心知识（本仓库之外的第二份"事实来源"）。
- 云端不通 = 不落盘：只允许 `writeback.ps1 -NoSync` 暂存，恢复后立即补推。

## R4 凭据
- Windows 凭据管理器统一管理（git credential manager）。
- 凭据失效 → 跑 `scripts/push-ready.ps1 -BrowserLogin`（浏览器授权）或 `-Token <PAT>`。
- token 永不落盘、永不进日志。

## R5 并发
- 多 Agent：写不同文件安全；写同一文件后推者云端胜出，被覆盖方重读后二次回写。
- `rebase.autoStash=true` 已开启，脏工作区 pull 前自动 stash / pop。
