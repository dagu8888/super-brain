## 4. Agent 运行机制（VERIFIED）

- 注册表 agents：agent_id/kind(chief|worker)/capabilities/task_types/permissions/verified/status/last_seen，当前 10 个全 active。
- **指挥权与执行权分离**：chief 七接口校验 kind=chief；worker 调指挥接口被拒（实测 PASS）。
- **派发铁律**：worker 须 verified=1 且 active 才可被 delegate；未验证只能领 probe 探针任务（trae-developer 已实测通过探针后独立接单）。
- Worker 线程每 5s 轮询领取，心跳写 heartbeats+agents.last_seen；Supervisor 30s 巡检，线程崩溃自动重启（worker_restarted 留痕）。
- 五个 chief 是"入口身份"（不常驻进程），经 HTTP/CLI 以口令/身份调用，canonical_user_id 统一解析为 dagu8888（单用户兜底）。

## 5. Task 执行机制（VERIFIED）

- 状态机：pending→doing→done｜failed｜dead｜cancelled；今日 20 任务全 done，无卡死。
- 原子领取：单条 UPDATE…WHERE status='pending' RETURNING，lease_token 每次+1（fencing）。
- 租约 120s，执行中每 30s 续租；Reaper 60s 回收过期租约（旧 Worker 提交被 fencing 拒绝，留痕 fencing_rejected）。
- 退避：RetryableError/DB锁 → 2^retry×30s，≤3 次 → dead；PermissionDenied 直接 dead。
- 幂等：UNIQUE(type,payload) 防重复入队；事件 dedupe_key 防重复事件。
- 取消：cancelled 仅 pending/doing 可转，领取后执行前二次检查。

## 11. 面向 3.0 的风险与约束清单

1. API 目前只有"指挥"接口，没有只读查询与推送——新增适配层，不动现有 /cmd。
2. 口令目前一律指挥权限——控制台应配**只读口令**（读状态）与指挥口令分级。
3. events 无自增序号——前端顺序检查/去重需用 created_at+event_id，或迁移加列（可选）。
4. HTTP 明文（用户已确认接受该风险）；18765 已公网——依赖口令强度+auth_failed 留痕，报告不含口令。
5. sessions 仅 7 条、语义薄——Memory 页面如实展示"暂无数据"部分，不虚构。
6. 禁止事项复核：本阶段未增加 Agent、未改组织、未重构 Runtime/任务机制/DB、未破坏 API——符合总指令 0.2。
