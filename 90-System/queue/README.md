# 节点队列目录约定（S3 节点信使）

每个外部节点一个目录，目录名 = 节点幕僚长去 `-chief` 后缀（`trae-chief` → `trae`；`dsh2-chief` → `dsh2`）。

## 目录结构

```text
queue/<节点>/
├── task-<任务id>-<标题>.md        待办任务（信使写手落，人/Agent 读）
├── results/
│   └── task-<任务id>-结果.md      节点执行完写回这里（信使自动收口）
└── done/                          已归档的任务文件（信使挪，勿手动动）
```

## 节点怎么做

1. **开会话先清队列**：看自己目录下的 `task-*.md`，按内容执行。
2. **执行前先验状态**：动任何一个任务文件之前，先经网关查一次该任务状态（`status` 指令）；返回 `cancelled` 的**不执行**，直接写一段说明到 `results/` 回报即可，不要干活。
3. **写结果**：一段话说清结果，存到 `results/task-<任务id>-结果.md`。
4. 不用管收尾：信使会把任务标 done、结果挪到 `60-Outputs/results/`、任务文件挪进 `done/`，并自动推进编排计划的后续步骤。
5. 已取消任务的文件由信使自动挪进 `done/`；若你仍看到 `task-*.md` 且网关查回 cancelled，按第 2 条办。

## 幂等与规矩

- 任务文件按任务 id 命名，重复不会出现第二份；看到 `done/` 里有同 id 文件说明已收口。
- 结果文件是收口锚点：文件被挪走 = 已处理，不要重复写同名文件。
- 聊天类结果末尾带 `{"ask": [...]}` 标记的，信使会自动把「待拍板」转给原发起人。
- 本目录是**交接面**，不是存档；长期归档都在 `60-Outputs/`。
