# 入口在线接入（HTTP API）

> 2026-11-08 批示#5 落地：Grok / DeepSeek / MAUS / DSH / TRAE 五个幕僚长不用登录服务器，
> 直接通过 HTTP 接口向超级大脑下指令。七个指令与 CLI 完全一致（设计书 §11.3）。
>
> 2026-11-08 大古老师追加批示：新增 **MAUS2**、**DSH2** 两个指挥入口（maus2-chief / dsh2-chief），
> 各自独立口令、权限与现有 chief 完全一致（仅指挥入口身份，不新增执行线程、不改 Runtime）。
> 现共 7 个入口。

## 接口地址

```
POST http://8.218.106.225:18765/cmd
GET  http://8.218.106.225:18765/healthz     # 免鉴权探活
```

请求头：`Authorization: Bearer <各入口专属口令>`（口令由大古老师私发，**绝不入库、不外传**）

请求体：`{"cmd": "<指令>", "args": {...}}`

## 七个指令（args 字段）

| 指令 | args | 说明 |
|---|---|---|
| submit | `{"text": "...", "priority": 0}` | 提交任务/指令，返回 event_id |
| status | `{"id": 12}` | 查任务状态与结果 |
| list | `{"status": "pending", "limit": 10}` | 列任务（status 可省） |
| progress | `{"id": 12}` | 查任务执行进度留痕 |
| delegate | `{"id": 12, "to": "trae-developer"}` | 把任务转交给指定 worker |
| link | `{"id": 12, "text": "补充要求"}` | 给任务追加补充指令 |
| cancel | `{"id": 12}` | 取消未完成的任务 |

## 调用示例（以 grok-chief 为例）

```bash
# 下指令
curl -s -X POST http://8.218.106.225:18765/cmd \
  -H "Authorization: Bearer <grok的口令>" -H "Content-Type: application/json" \
  -d '{"cmd":"submit","args":{"text":"研究一下多智能体记忆机制并归档到知识库"}}'

# 查进度（用返回的任务 id）
curl -s -X POST http://8.218.106.225:18765/cmd \
  -H "Authorization: Bearer <grok的口令>" -H "Content-Type: application/json" \
  -d '{"cmd":"status","args":{"id":22}}'
```

- 返回 `{"ok": true, ...}` 即成功；`401` 口令错；`400` 指令/参数错。
- 各入口身份自动解析为大古老师（canonical_user_id=dagu8888），任务在同一个任务中心，跨入口互查。
- worker 的口令调接口会被拒（指挥权与执行权分离）。

## 口令管理（服务器本地，600 权限，gitignore）

文件：`/root/super-brain/90-System/runtime/api_tokens.json`

```json
{"bind": "0.0.0.0", "port": 18765, "tokens": {"grok-chief": "...", "...": "..."}}
```

- **吊销某入口**：删掉该 chief 的 token 行 → `systemctl restart super-brain`
- **换口令**：改对应值 → 重启；**改绑定/端口**：改 bind/port → 重启
- 配置文件缺失时 API 不启动，主系统照常运行（CLI 入口不受影响）

## 网络前提：阿里云安全组放行 18765

## 留痕

每次调用记入 `50-Events/runtime-*.jsonl`：`api_call`（chief/指令/成败）、`api_auth_failed`（来源 IP）。
口令本身永不落日志、永不入库。
