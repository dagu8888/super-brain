> 直接通过 HTTP 接口向超级大脑下指令。七个指令与 CLI 完全一致（设计书 §11.3）。

## 接口地址

```
POST http://8.218.106.225:18765/cmd
GET  http://8.218.106.225:18765/healthz     # 免鉴权探活
```

请求头：`Authorization: Bearer <各入口专属口令>`（口令由大古老师私发，**绝不入库、不外传**）

请求体：`{"cmd": "<指令>", "args": {...}}`

## 七个指令（args 字段）

| 指令 | args | 说明 |
|---|---|---|
| submit | `{"text": "...", "priority": 0}` | 提交任务/指令，返回 event_id |
| status | `{"id": 12}` | 查任务状态与结果 |
| list | `{"status": "pending", "limit": 10}` | 列任务（status 可省） |
| progress | `{"id": 12}` | 查任务执行进度留痕 |
| delegate | `{"id": 12, "to": "trae-developer"}` | 把任务转交给指定 worker |
| link | `{"id": 12, "text": "补充要求"}` | 给任务追加补充指令 |
| cancel | `{"id": 12}` | 取消未完成的任务 |

## 调用示例（以 grok-chief 为例）

```bash
# 下指令
curl -s -X POST http://8.218.106.225:18765/cmd \
  -H "Authorization: Bearer <grok的口令>" -H "Content-Type: application/json" \
  -d '{"cmd":"submit","args":{"text":"研究一下多智能体记忆机制并归档到知识库"}}'

# 查进度（用返回的任务 id）
curl -s -X POST http://8.218.106.225:18765/cmd \
  -H "Authorization: Bearer <grok的口令>" -H "Content-Type: application/json" \
  -d '{"cmd":"status","args":{"id":22}}'
```

- 返回 `{"ok": true, ...}` 即成功；`401` 口令错；`400` 指令/参数错。
- 各入口身份自动解析为大古老师（canonical_user_id=dagu8888），任务在同一个任务中心，跨入口互查。
- worker 的口令调接口会被拒（指挥权与执行权分离）。

## 口令管理（服务器本地，600 权限，gitignore）

文件：`/root/super-brain/90-System/runtime/api_tokens.json`

```json
{"bind": "0.0.0.0", "port": 18765, "tokens": {"grok-chief": "...", "...": "..."}}
```

- **吊销某入口**：删掉该 chief 的 token 行 → `systemctl restart super-brain`
- **换口令**：改对应值 → 重启；**改绑定/端口**：改 bind/port → 重启
- 配置文件缺失时 API 不启动，主系统照常运行（CLI 入口不受影响）

## 留痕

每次调用记入 `50-Events/runtime-*.jsonl`：`api_call`（chief/指令/成败）、`api_auth_failed`（来源 IP）。
口令本身永不落日志、永不入库。

## 组织管理：Agent 与入口可随时增减（2026-11-08 方案 A）

**原则：以 `agents` 表为准，代码不写死名单。** 增减 Agent 不需要改代码、不需要重启、不需要重新部署。

### 三个管理指令（chief 权限，走同一个 /cmd）

| 指令 | 参数 | 作用 |
|---|---|---|
| `add-agent` | `{"id","kind":"worker\|chief","capabilities":[...],"task_types":[...],"verified":bool}` | 注册新 Agent，立即 active |
| `disable-agent` | `{"id"}` | 停用；worker 线程 30 秒内自动回收 |
| `enable-agent` | `{"id"}` | 恢复；worker 线程 30 秒内自动拉起 |

```bash
curl -X POST http://<host>:18765/cmd \
  -H "Authorization: Bearer <口令>" -H "Content-Type: application/json" \
  -d '{"cmd":"add-agent","args":{"id":"analysis2-worker","kind":"worker","capabilities":["research"],"task_types":["research"],"verified":true}}'
```

### 运行机制

- **启动时**：Supervisor 读 `SELECT agent_id FROM agents WHERE kind='worker' AND status='active'` 逐个拉起线程。
- **运行中**：每 30 秒对账一次——注册表新增 active worker → 自动起线程（`worker_spawned`）；被停用 → 发停止信号、退出后回收（`worker_stopping` / `worker_removed`）。
- **身份与线程**：线程名 = agent_id，心跳写入 `heartbeats`，派单按 `task_types` 匹配，未验证（`verified=0`）只能领 probe。
- **保护**：不能停用自己；不能停用最后一个 active（worker/chief 各自至少留一个）。
- **留痕**：`agent_status_changed` / `agent.created` 事件 + `perm_audit`，全可追溯。

### 已验证（2026-11-08 实测）

| 动作 | 结果 | 证据 |
|---|---|---|
| `add-agent test-agent-worker` | 成功，35 秒内自动起线程 | `worker_spawned`；进程线程 11→12；心跳持续写入 |
| `disable-agent test-agent-worker` | 成功，35 秒内线程回收 | `worker_stopping`；线程 12→11；心跳停更 |
| `enable-agent chat-worker` | 成功，线程自动复活 | 心跳 0 秒前 |

### 注意

- 新增 chief 只是"能用口令下指令的身份"，还要在 `api_tokens.json` 里配独立口令才生效（口令永不入库）。
- 新增 worker 必须有对应的 `HANDLERS` 处理器，否则接单即 dead；无对应处理器时先按 `assist` 走入口协作池。
- 停用 Agent 不影响历史任务与事件留痕。
