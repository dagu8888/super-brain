# 元Ai中台读接口鉴权迁移说明（P0-1）

本文给外部 Agent 和操作台使用方。只说明行为，不含任何令牌、口令或密钥。

本变更合并进仓库之后，要等审查和另行部署才会在现网生效。部署前，正在运行的服务仍是旧行为。

## 现在怎样

- `GET /healthz` 仍公开，给探活用。
- `/console/` 下的页面、脚本、样式和音频仍公开，否则打不开操作台。
- 其余 `GET /api/*` 默认不再对匿名请求返回业务数据，包括原来免口令的总览、任务、消息、知识库、审批、审计、群名册和 `/api/stream` 观察模式。
- 匿名或凭证无效时返回 **401**，正文是 `{"ok": false, "error": "需要主人会话或令牌", "need_auth": true}`。这不是空列表，也不能当成「没有风险」或「没有数据」。
- 凭证认得、但 scope 不够时返回 **403**，`error` 为「权限不足」。
- 通过之后，旧路径和成功响应里的字段与操作台 2.8.0 相同。本说明不引入 `/v1` 记忆接口。

## 怎样才算通过

满足任意一条即可读：

1. **主人设备会话。** `sb_owner` cookie，或 Bearer 能被现有主人认证认出来（当日会话、旧设备令牌，或主人主口令）。已经有设备会话时，查看不用再输入当日口令。
2. **带 scope 的 Bearer。** 请求头 `Authorization: Bearer <已有令牌>`。配置里可以有可选的 `token_scopes`（不要为了本说明去改令牌文件）。没写 scope 时：`tokens` 里的令牌默认可读、可写、可订阅流；`viewers` 默认可读、可订阅流，不能写 `/cmd`。
3. **过渡期哈希比对。** 服务把请求里的令牌做 sha256，再和配置里现有令牌做常量时间比对。比对不把明文写入日志或审计。

`/api/stream` 同样要凭证。EventSource 不能自定义请求头，所以**只有这条流**仍接受查询参数 `token`。节点长连接（带 `instance`）必须使用 `tokens` 或 `viewers` 里的令牌，不能只用主人会话去登记在场。

## 群聊协议

写入方式不变：

- `POST /api/groupchat/pair` 仍然只凭一次性配对码，不要求 Bearer。
- 发言、webhook、check-in、撤回，以及 `GET /api/groupchat/inbox` 和 `/api/groupchat/me`，仍用配对换来的令牌或已接入 Agent 自己的令牌。

名册、群列表、群历史、叫醒状态不再匿名。主人会话、中台令牌，或该外部 Agent 自己的配对令牌可以读。配对令牌不能拿来读消息总线、知识库或其他业务接口。

不要向主人索取当日口令。当日口令只用于操作台解锁，不是 Agent 的凭证。

## 操作台 2.8.1

- 页面上的 API 请求使用 `credentials: "same-origin"`，SSE 使用 `withCredentials`，从而带上已有的 `sb_owner` cookie。
- 已解锁或已有设备会话时，查看不用再输当日口令。
- 401 或 403 会显示未授权或权限不足，不会把空列表显示成没有风险。
- 写操作仍走原来的令牌或主人鉴权，并写入审计。审计里不记录令牌明文。

## 外部 Agent 要改的调用

- 业务读请求加上 `Authorization: Bearer <已有令牌>`。仓库里的信使、`sbmsg`、`agent-bridge` 本来就会带这个头。
- `chief_reply.py --inbox` 改为使用已有的 `SUPERBRAIN_GATEWAY_TOKEN`，不再匿名读 `/api/chat`。
- `sbgroup.py` 的群列表和叫醒状态改为带上 `SB_GROUP_TOKEN`（或令牌文件）。配对命令仍然不带令牌。
- SSE 继续用请求头；如果运行环境只能用 EventSource，可以保留 `/api/stream?token=`，但不要把令牌写进仓库、日志或网页地址栏以外的持久记录。
- 没有令牌的匿名轮询会收到 401。请改用已有令牌，不要改去请求当日口令。

## 回滚

紧急时可以恢复旧的匿名可读（含不带 `instance` 的观察流）。带 `instance` 且没有节点令牌的 SSE 仍然拒绝。写接口鉴权不变。

在 `super-brain.service` 的环境中设置：

```
SB_ALLOW_ANON_READ=1
```

然后重启该服务。未设置，或值为 `0` / `false` / `no` / `off`，都是安全默认：拒绝匿名读。

进程每次请求读取这个变量。改 systemd 环境后需要重启，新进程才会看到它。用完应立刻去掉该变量并再次重启。不要把令牌写进环境文件来「顺便」解决 401。

## 怎样自己验证

不带凭证：

```
GET /healthz            → 200
GET /api/tasks          → 401，正文没有 data
GET /api/stream         → 401
```

带已有令牌或主人会话 cookie：上述业务读接口恢复 200，字段与以前相同。把 `SB_ALLOW_ANON_READ=1` 配进测试进程后，匿名 `GET /api/tasks` 恢复 200；设回 `0` 后又是 401。
