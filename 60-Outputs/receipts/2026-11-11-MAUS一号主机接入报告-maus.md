## 一、它在建什么

一套「**一个网关派单、一个仓库当唯一事实源、多 Agent 分包执行、成果强制回写**」的私人 Super-Agent 中枢。我读到的骨架：

- **唯一事实源**：GitHub 私有仓库 `dagu8888/super-brain`。本地一律是工作副本；云端为准。分区各司其职：`00-Inbox/` 收纳、`10-Knowledge/` 沉淀（唯一写入口是 knowledge-worker）、`20-Skills/`、`30-Reviews/`、`40-Agents/` 配置即代码、`50-Events/` 事件只追加、`60-Outputs/` 成果、`70-Assets/`、`80-Templates/`、`90-System/` 运维脚本。
- **指挥 / 派单层**：网关 `http://8.218.106.225:18765`，`POST /cmd`，Bearer 专属口令。七个动词 `submit / list / status / progress / delegate / link / cancel`；`GET /healthz` 免鉴权探活。七个 chief 指挥入口（grok / deepseek / maus / dsh / trae + 追加的 maus2 / dsh2）共享同一任务中心（`canonical_user_id=dagu8888`），跨入口互查；各入口独立口令、可单独吊销，口令存服务器本地 `api_tokens.json`（600 权限、gitignore），**永不入库、永不落日志**。另有 `add-agent / disable-agent / enable-agent` 三个管理动词，Agent 增减以数据库 `agents` 表为准、不改代码不重启。
- **事件驱动（Router）**：事件 → 先留痕 `50-Events` → ①快过滤（`filters.yaml`，纯规则、不调模型，DROP / ALLOW / URGENT 三级）→ URGENT 直接派单并立即回执；ALLOW 先查 `routing_table[thread_id]` 命中就直通同一 Worker（不换人），未命中才走 ②慢判断（轻量模型出 `{intent, worker, confidence}`，低于阈值回问澄清）→ 派单 → Worker 完成。Router 先回「已收到，处理中」（<1s），异步执行，不卡对话。
- **实时消息总线 v1（2026-11-10）**：Agent 之间的对话**不走 `submit`**（会进 events、被 chat-worker 代答，看着像有人回其实是中台 LLM 在代答）。改用 `msg / reply`，只写 `messages` 表，经 `GET /api/stream` 以 `event: msg` 推**完整 JSON（含正文、收件人）**，`GET /api/rollcall/<msg_id>` 查点名回执。节点侧 `tools/bus/agent-bridge.py` 长连即在场心跳，box 侧 `tools/bus/sbmsg.py`。验收分三层：进程在跑 / 在场 / 能收发并回复——不能再被「进程在、心跳在、其实收不到正文」骗到。`from` 由口令识别，不可伪造。
- **执行层 Worker**：`40-Agents/workers/` 下 knowledge / code / chat 三个；`90-System/queue/<节点>/` 是节点信使投递任务文件的交接面（目录名 = 幕僚长去掉 `-chief`），节点读任务前先经网关 `status` 验状态，`cancelled` 的不执行、只写说明回报。
- **收口与完成定义**：节点把结果写 `results/task-<编号>-结果.md` 并推仓库，信使自动标 done、结果挪 `60-Outputs/results/`、任务文件挪 `done/`、推进编排计划后续步骤。`90-System/sop/强制回写SOP.md` 定义：**任务完成 = 成果已 push 云端 + 已向 Router 汇报**，缺一不算完成；10 分钟催办、30 分钟升级、每周日回写审计。看门狗（`watchdog.yaml`）每 10 分钟巡检心跳 / 队列积压 / 同步状态 / Inbox 积压。
- **权限与红线**（`40-Agents/权限与同步规则.md`）：写权限最小化；knowledge 沉淀只有 knowledge-worker 一个写入口；`40-Agents/`、`90-System/` 任何 Agent 不得自动改，只能人工 PR；分区写入、文件名带署名、写前先拉、写后即推（`sync.sh`，`pull --rebase --autostash`，禁 `--force`）。我（Mausbot）读全仓库、只写 `00-Inbox/` 与 `60-Outputs/`、禁写 `40-Agents/` 与 `90-System/`。

一句话：**网关管「派活与状态」，仓库管「知识与会话留痕」，信使管「收口」，Router 管「分诊」，Agent 只管「按分区写完自己的活并推上去」。**

## 四、中台怎么派活（我这边怎么接）

1. 派单 → 网关 `submit` 生成 `event_id` → 任务中心 → 信使把 `task-<编号>-<标题>.md` 投到 `90-System/queue/<我的节点>/`。
2. 我开会话先清自己队列；读到任务文件后**先 `status` 验状态**，`cancelled` 的只写一段说明回报、不干活。
3. 按分区干活，结果写 `60-Outputs/results/task-<编号>-结果.md`（本轮指令指定的文件路），推仓库；推送不通先查本机代理。
4. 完成定义：成果已 push 云端即回写完成，信使自动收口；本轮无本机命令环境，用 GitHub 网页直推云端替代 `sync.sh`（云端即唯一事实源，效果等价）。
5. 实时对话 / 点名（ping）走 `msg → /api/stream → reply → /api/rollcall`，**不进 events 路由、不触发 chat-worker 代答**；点名回执标明 `layer=transport`。
6. 常驻守候用脚本（节点桥 / 看门狗 / 定时任务），**不用 LLM 高频轮询**。

### 关于第 1 项（凭据自检）为什么没做成

端口令纪律（只存本机安全存储或环境变量，绝不写进任何仓库文件、日志或回写）与这一轮的工具有冲突：这一轮挂载的是**内置浏览器**，没有桌面 / Local VM / 本机 shell；Vault 里那把口令按设计不把明文交到我手上，我也不能把它拼进网页脚本或请求里——那样就等于把它写进了页面与日志。做了一次**不带口令、无副作用**的 `/cmd` 探测，返回的不是有效业务响应，因此不构成自检、也不据此推断身份。

**补齐方式**：在有本机命令环境的一轮，从安全存储读出该口令、只在命令里以环境变量引用，`POST /cmd` 发一次 `heartbeat` 或 `status`，把网关返回的身份名**原样**回报并补记到身份卡；或由大古本人执行一次自检后把身份名告诉我。在此之前，身份卡里「网关身份」一栏是依据仓库文档的顺序推断，标注了未自检，不冒充网关实测值。
