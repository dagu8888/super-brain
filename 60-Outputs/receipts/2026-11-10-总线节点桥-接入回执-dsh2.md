## ⑥ OpenMausBot 签发本机口令 — 签不了，报错原文如下

环境：本机 OpenMausBot 桌面版在运行（PID 9804，`C:\Users\大古老师\AppData\Local\Programs\openmausbot\`），内嵌 server 监听 127.0.0.1:8799；本机 Node v22.14.0（CLI 实测能跑，官方要求 Node 24+，如需要可升级）。CLI 用安装包内 `resources\server\openmausbot.js`（4.9MB，`token create` 子命令存在）。

1. `node openmausbot.js token create dsh2-notebook-duty --out D:\DSH\super-brain-bus\openmaus-token.txt`：
   ```
   error: not allowed: OpenMausBot refused this write because the installed desktop app requires a paired session token. Set OPENMAUSBOT_TOKEN as described in docs/mcp-server.md.
   hint: this needs a paired session with the right scope: `openmausbot connect` mints one on this computer
   ```
2. `node openmausbot.js pair`（connect 需要 pairing code，尝试本机铸造）：
   ```
   server refused to mint a pairing code: forbidden: this change must come from the desktop app or a paired device
   ```
3. 直连 `POST http://127.0.0.1:8799/api/auth/sessions`（匿名）→ `403 已禁止`（GET 同路径匿名可读，`{"sessions":[],"current":null}`，证明链路通、只差写权限）。

已排除的替代路径：桌面 App 数据目录（Roaming\openmausbot、Local Storage、`.openmausbot\hook-tokens`、server-child lease 文件）无现成 admin session token 可用。**结论：签发动作被 OpenMausBot 安全模型限定为"必须来自桌面 App 或已配对设备"，本机无已配对凭据。**

需要大古配合的一步：在 OpenMausBot 桌面 App 里生成一个配对码（或从已配对设备发起），把配对码交给本会话，我即可执行 `openmausbot connect http://127.0.0.1:8799 --code <CODE> --out <FILE>` 取 session token，再完成 `token create` 并把口令存入本机文件回报路径；或直接在 App 内签发后告知存放位置。
