## 二、怎么拉起（插件主体）

`tools/duty-room/dsh1-activator.py`（纯标准库，零 LLM，零网关轮询）：

1. 3 秒扫描本节点队列 `90-System/queue/dsh/task-*-*.md`（courier 的 SSE 信号驱动落文件，
   本插件只监听文件系统——信号链沿用 courier，不另开 SSE 连接）；
2. 新任务 id → `POST /cmd status`（chief 口令）验状态，**非 pending 不执行**（纪律1：cancelled 不执行）；
3. `subprocess` 拉起 `cmd /c dsh.cmd --profile headless -`，任务全文从 stdin 喂入；
4. 会话退出后检查 `results/task-<id>-*.md`；缺失则插件**如实**落失败结果文件；
5. 结果文件 `git add -f + commit + pull --rebase --autostash + push`（重试×3）上云，
   hk-server 定时同步后由服务端信使收口——完成链完全自动。

## 三、失败怎么防

- 单任务硬上限 25 分钟，超时 `taskkill /T /F` 进程树击杀，随后落失败结果（任务收口为
  done 带失败说明，**宁可如实失败，不留死信等改派**）；
- 网关状态校验重试 3 次仍不可达 → 本轮跳过，任务留在队列等下轮（诚实优先于冒进）；
- push 失败重试×3 后保留本地 commit，日志记 PUSH_GIVEUP，下轮/人工补推（commit 不丢）。

## 四、同一任务不会跑两次（三层防重复）

1. 状态文件 `%USERPROFILE%/dsh1-activator-state.json`：finished / in-flight 按 id 登记，
   崩溃重启幂等；
2. `results/task-<id>-*.md` 已存在即视为已交付（服务端收口锚点存在=完成）；
3. 执行锁 `queue/dsh/.activator/<id>.lock`（O_EXCL 原子建），启动时清扫无 in-flight
   登记的残留锁。

**红线**：`results/` 下绝不允许出现会话最终结果以外的任何 `task-<id>-*` 文件——服务端信使对
该模式一律收口，中间标记（如"执行中"）会提前关单；故锁/标记一律放 `.activator/`。

## 五、纪律遵守

- 只动 `queue/dsh/`（+仓库内 tools/reports）；不碰其他节点队列；不碰 `90-System/runtime`（只读参照）；
- chief 口令只存用户级环境变量 `SB_TOKEN`（HKCU\Environment），不写文件/日志/仓库；
  启动器 bat 纯 ASCII（UTF-8 中文注释在 GBK 代码页 cmd 下乱码会破坏解析——19:45 实踩，已改）；
- 常驻方式：启动文件夹 `DSH1-Activator.bat`（指向仓库内 `dsh1-activator-start.bat`）+
  bat `:loop` 自愈（进程退出 10 秒后自动重启），与 courier 同法。

## 六、如实声明：认领超时窗口

插件**不使用** `/cmd pull` 认领（pull 无目标过滤参数，会抢协作池内/他节点任务）。
因此点名任务在执行期间保持 pending：若执行超 600 秒且未豁免，会触发 D2 告警+改派
（改派重置窗口；courier SSE 在线故一般改派回本实例）。缓解：常态任务 2–15 分钟即完成；
建议 Muse 对长任务统一加 `no_claim_timeout=true`（与 #334 同式）。补充：pull 无过滤与
waker v2 回执结论互为印证（独立复读 `runtime.py:914` claim_task 的 WHERE 子句）。
