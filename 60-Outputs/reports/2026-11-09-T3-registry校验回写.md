## 实现内容

1. **新建 `registry` 名册表**（migrate_v2 幂等迁移）：`name / kind(instance|worker|chief) / location / agent_ref / status`。worker 与各幕僚长由 `agents` 表自动在册，无需重复登记。
2. **种子实例**：`DSH一号@主机 → dsh-chief`、`DSH二号@笔记本 → dsh2-chief`、`Trae@笔记本 → trae-chief`。下线不删档，`status='retired'` 即被拒且留痕。
3. **网关校验**（`chief_execute`）：
   - `submit` 新增可选 `to` 点名：不在册 → 当场拒绝不入队；在册 worker → 直接落单；在册实例/幕僚长 → 入协作池并点名（其对应身份 pull 领取）。
   - `delegate` 先过名册：不在册 → 当场拒绝；实例/幕僚长 → 转协作池点名；worker → 走原有验证派单路径。
4. **兼容性**：不带 `to` 的 submit 与原有七接口语义零变化，8 个幕僚长现有接入不受影响。

```json
POST /cmd {"cmd":"submit","args":{"text":"T3验收坏名字","to":"Grok四号@火星"}}
→ {"ok": false, "registry_rejected": true,
   "error": "Grok四号@火星 不在名册或已下线，已当场拒绝，未入队"}
```

```json
POST /cmd {"cmd":"delegate","args":{"id":1,"to":"不存在的家伙"}}
→ {"ok": false, "registry_rejected": true,
   "error": "不存在的家伙 不在名册或已下线，已当场拒绝，未入队"}
```

```json
→ {"ok": true, "task_id": 227, "to": "DSH一号@主机", "mode": "assist",

```
